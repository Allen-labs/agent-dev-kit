# Review

对指定范围的改动做结构化评审，输出按优先级排序的可执行建议。

## 改动范围

- 默认：`git diff HEAD~1`（最近一次提交）
- 指定范围：$ARGUMENTS（如 `HEAD~3`、`src/api/**`）

## 检查清单（5 项）

1. **代码质量与可读性**：命名清晰？函数是否过大？有无重复逻辑？
2. **安全**：注入风险（SQL/XSS/命令）？密钥或敏感信息泄露？权限校验缺失？
3. **性能**：明显的 N+1 / 循环内 IO / 无界查询？
4. **测试覆盖**：新增/修改的逻辑有没有对应测试？边界情况？
5. **文档完整性**：公开 API / 行为变更是否同步更新了文档？

## 输出格式

- 按严重程度排序：🔴 必须修 → 🟡 建议改 → ⚪ 可选
- 每条给出：位置（文件:行）+ 问题 + 具体修法
- 结尾给总结：哪些可以合并、哪些需要补测试
